- Browser sessions use hashed opaque identifiers, Secure/HttpOnly/SameSite=Strict cookies, a 15-minute rotating lifetime, a 12-hour absolute limit, exact-origin CSRF enforcement, sign-out revocation, and expiry checks.
- One-use pairing grants issue desktop refresh credentials once and D1 retains only hashes. Short access tokens are capability-scoped to desktop sync and optional provider bridging; device revocation invalidates both refresh and access tokens, and re-pairing creates a new device identity.
- The desktop identity client rejects non-HTTPS remote origins, stores the refresh credential through the existing OS credential abstraction, never persists the pairing grant or short access token, validates protocol/capability/expiry responses, and fails without exposing server details.
- Recovery codes are shown once, stored only as hashes, attempt-limited, one-use, and rotated. Recovery replaces the active passkey and revokes prior passkeys and all Web sessions.
- All-app-credentials-lost recovery is an offline, output-only SQL preparation tool with audit insertion. It revokes Web, desktop, owner, and recovery credentials without connecting to D1 or deleting task/sync history.
- Authentication, recovery, pairing, and token endpoints have persisted rolling attempt limits. Strict JSON parsing rejects duplicate properties, and the active-owner constraint is enforced in D1 to close concurrent bootstrap races.
- The permanent Connect Cloudflare Core boundary now generates Authorization Code + S256 PKCE requests without a client secret, validates callback state, exchanges short-lived authorization, accepts the redirect through a fixed loopback callback, and requires token revocation.
- A resumable provisioning coordinator checkpoints only non-secret resource state across account resolution, D1 creation/adoption, versioned Worker deployment, migrations, health verification, and automatic initiating-desktop pairing.
